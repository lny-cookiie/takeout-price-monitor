# 进度与实验记录

这个文件夹只放「过程发生了什么」：每天做了什么、每次实验怎么配置、跑了多少组、成功多少、为什么失败、下一步做什么。它和另外两个库分工不同：

| 文件夹 | 只放什么 | 不放什么 |
| --- | --- | --- |
| `前期调研/` | 方案调研、技术选型、实施计划和历史决策依据 | 日常进度和逐组实验数据 |
| `产品目标/` | 当前有效的产品判断：定位、形态、护城河、Benchmark、合规、估值 | 过程流水账 |
| `进度与实验记录/` | 实施进度、批次实验配置与结果、失败与重试记录、验收数据汇总 | 产品判断和外部市场结论 |

失败与修复的经验条目仍然放在 `前期调研/41_失败与修复知识库.md`，因为它是长期参考文档；本文件夹只记录「这次实验遇到了什么」，两者互相引用。

## 命名与维护约定

1. 实验记录命名：`实验记录_<标签>_<日期>.md`，标签用「基线A」「优化B」这种一眼能看懂的名字。
2. 每份实验记录必须写清：代码冻结在哪个提交、批次目录在哪、目标是什么、统计口径是什么、逐组结果、汇总数字、失败原因、下一步。
3. 只追加不删除：历史组的明细在批次目录的 `rows.jsonl` 里，实验记录里保留汇总和结论；结论变了就在新日期里写取代关系，不覆盖旧结论。
4. 进度文档按日期分节追加，不重写历史；涉及隐私和账号的内容不写进来。
5. 每次更新后，在对应实验记录顶部把「截至更新时间」改掉，并在 `04_验收数据汇总.md` 同步关键数字。

## 和其他库的挂钩

- 排需求或报价前，先看 `产品目标/03_市场Benchmark与当前差距.md`，再回本库确认最新实测数据。
- 每次失败整理成经验后，写入 `前期调研/41_失败与修复知识库.md`，本库只留运行编号和现象。
- 验收脚本、批次目录、冻结基线工具见项目 README 和 `scripts/`。

# 产品目标库

这个文件夹是「外卖三平台比价工具」的产品层事实来源，用来回答三个问题：我们要把它做成什么、现在差多远、值多少钱并且怎么合规地变现。它不替代技术文档和验收记录，而是把技术结果翻译成产品判断，供每一次功能取舍、报价和对外沟通时先查一遍。

## 目录

| 文件 | 内容 | 什么时候看 |
| --- | --- | --- |
| `01_产品定位与目标形态.md` | 产品愿景、目标客户、三种产品形态、非目标、北极星指标 | 定需求、砍需求、对外介绍时 |
| `02_核心能力与护城河.md` | 现有能力清单、卖点、护城河强弱分析、可复制性 | 判断某个能力值不值得投入时 |
| `03_市场Benchmark与当前差距.md` | 同类产品价格与能力对照、当前实测数据、差距清单 | 定价、竞品分析、路线图排序时 |
| `04_约束与合规.md` | 法律与平台约束、真实判例、红线清单、合规检查表 | 任何对外销售、演示、交付之前 |
| `05_估值与变现路径.md` | 三种估值方法、价格区间、客户类型、变现路径排序 | 报价、融资、合作谈判时 |
| `06_迭代记录.md` | 每次更新的日期、依据、结论变化 | 每次修改本库时 |

## 维护约定

1. 本库跟着项目走，代码和验收数据一变就更新对应数字，尤其是 `03` 里的稳定性、耗时和差距表。
2. 每次更新必须写进 `06_迭代记录.md`：日期、依据（运行编号、批次目录、外部来源）、改了什么结论。
3. 外部价格和判例要附链接和查看日期；超过一个季度没有复核的价格标注「待复核」。
4. 结论分三档写清楚：已实测事实、合理推断、待验证假设。不要把推断写成事实。
5. 本库不写客户隐私、账号、设备序列号等敏感信息；引用运行编号可以，截图证据留在系统的证据库里。

## 与开发流程的挂钩方式

- 每次排优先级前，先看 `03` 的差距表，确认要做的功能是缩小「稳定性、效率、完整度、合规」中的哪一项差距。
- 每次改完代码跑完验收，把新的成功率和耗时回填到 `03`，并在 `06` 记一行。
- 任何对外报价或演示之前，先过一遍 `04` 的合规检查表；没有律师意见之前不承诺「可商用」。

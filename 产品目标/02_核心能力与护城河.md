# 核心能力与护城河

## 已经具备的能力（按真机验证过的算）

1. 三平台串行编排：同一台手机上按京东、美团、淘宝闪购顺序跑完，组内时间差控制在十分钟量级，避免多平台并发抢前台。
2. 纯视觉采价链路：淘宝没有可用的读屏节点，全部靠截图、短提示定位、颜色与比例坐标、键盘搜索键提交；美团结算页是 WebView，靠整页截图读文字；京东结算页是自绘页面，同样靠截图读取。这套「视觉兜底」能力是当前最值钱的工程资产。
3. 证据链：结算页整页证据、门店证据、商品证据三件套，顶部隐私区域涂黑，费用行做加减核对，金额读两次一致才采用。
4. 购物车安全：任务开始前确认空车，只加目标单品，只撤本次增量；美团用全局购物车「管理」模式删除，淘宝用购物车面板「清空」兜底；恢复状态用底栏文字和购物车页双重确认。
5. 失败知识库与自愈：每次失败自动记录平台、错误码、清理状态和最近步骤；已整理 18 条以上经验，覆盖搜索提交方式、店内实时搜索、门店名截断、结算页读取超时、验证码识别等；每次开工先检索经验再跑。
6. 验收工具：基线冻结、20 组批次、组成功率、P50/P90、证据复核脚本，能持续量化「有没有变好」。
7. 风控保护：识别验证码即停止且不点击，调度器自动暂停平台，批次遇验证码立即停批，组间冷却两分钟。
8. 自愈闭环（半自动）：失败自动记录并关联失败模式注册表，脚本自动聚合失败签名、找出未登记问题和已修复又出现的回退风险，批次结束自动生成失败摘要；修复后的真机验证和知识注入还需要人参与。

## 卖点（对客户怎么讲）

- 「不是截图给你看，是给你一张能对账的结算页证据。」
- 「购物车动过必恢复，恢复不了会停下来等人，不会把你的车搞乱。」
- 「平台改版我们能自己收敛一部分，有失败知识库，不用每次从零修。」
- 「同一组三家报价在十分钟内拿齐，时间差和实际分店都记录在案。」

## 护城河分析（诚实版）

| 资产 | 护城河强度 | 原因 |
| --- | --- | --- |
| 三平台视觉链路代码 | 中 | 工程量大、坑多，但可被有经验的团队复制，平台改版会贬值 |
| 失败知识库与自愈机制 | 中偏强，可升级为强 | 需要长期真机踩坑积累，复制成本高，是当前最独特的资产；目前记录和检测自动、归纳和注入靠人，补全后护城河更强 |
| 证据链与购物车安全设计 | 中 | 设计不难，难在长期稳定执行，属于信任资产 |
| 客户授权与合规关系 | 强（若建立） | 真正难复制的是合法数据来源和客户信任，目前还没有 |
| 数据积累 | 弱 | 目前没有长期历史库，单次采价不构成数据壁垒 |
| 品牌与渠道 | 弱 | 还没有对外品牌和销售渠道 |

结论：现阶段真正的护城河是「踩坑经验 + 安全设计 + 验收体系」的组合，不是代码本身。要把它变成可持续的护城河，必须补上合规授权、客户关系和长期数据积累。

## 容易被低估的成本

- 平台改版适配：每次应用更新都可能让视觉路径失效，需要重新标定和验证。
- 风控对抗：验证码、账号限制、设备指纹会随使用频率上升，必须靠降频和人工验证，不能靠技术绕过。
- 交付与运维：每个客户要独立设备、账号、点位和培训，边际成本不低。
- 法务成本：对外销售前需要律师意见、合同条款、数据处理说明。

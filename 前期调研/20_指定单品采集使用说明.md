# 指定单品采集使用说明

## 一页读懂

给京东 BD 和运营使用。保存包销商品清单后，每次选择一家门店的一款商品，自动加购一份、读取结算，再移除本次加购。结果含商品现价、结算应付、可见费用、脱敏截图和每一步日志。当前先验证京东，不提交订单。

没有真实包销清单也可以测试：新增一项“试采商品”，填写门店、商品名和规格。试采不代表这款商品属于包销。

## 怎么使用

1. 用主服务打开 `http://127.0.0.1:4318/ue?collection=1`。静态 UI 预览不连接采集后台。
2. 在“数据管理 → 包销品清单”下载 CSV 模板，填好后导入。先看预览，再确认保存。也可导入 JSON 对象数组。最低字段是城市、区县、品牌、完整分店名、商品名、规格、是否包销。地址由系统核实，不用 BD 填写。
3. “是否包销”填是或否，未核实时留空；JSON 使用 true、false、null。缺标记会显示待补齐，不能直接作为包销品采集。表版本可填写内部清单日期或版本号，系统另记导入时间。
4. 无正式清单时点击“添加试采商品”，填写同样的门店和指定商品资料，保存一次即可复用。不要把试采商品标为包销品。
5. 在“竞对采集”选择商品，以及已保存的测试账号与配送地址。手机用 USB 连接电脑、解锁、联网，并在京东登录该账号、选好该配送地址。点击“开始采集”，等待结果。不要同时使用这台手机。
6. 查看“报价是否取得”和“购物车是否恢复”。展开报价可看各项费用和截图；展开执行日志可看每一步、返回值及耗时。缺失显示未取得，并保留原因。日志可导出 JSON，报价可导出 CSV。
7. “商品诊断 → 实际采集 → 竞对同品”查看真实结果。三平台未同时接入时，缺少平台显示未取得，不生成三平台最低价。经营订单和成本未接入时，收益显示未接入。

## 失败后怎么办

找不到目标、门店或规格不一致时，不能改采其他商品。账号、配送地址或应用版本变更，交由接入人员核实。购物车恢复未确认时设备暂停，先核对现有商品，不能直接清空用户购物车。

当前手机 UI 采集依赖可读页面。程序可唤醒熄屏设备，无法绕过密码锁屏。预约执行需要手机届时连线、联网且可操作；无人值守设备能力另行验收。

## 结果怎样判断

商品现价与结算应付是不同指标。结算包含一份商品在当前账号、时间、配送地址和已应用优惠下的实际应付。不能把前端优惠直接解释成京东出资。只有页面文字与模型读数一致的金额才发布为已核对；单靠模型读出的内容保留为待复核。

性能目标仍需真机连续验收。回放和浏览器通过，不能代替二十次真实任务通过。

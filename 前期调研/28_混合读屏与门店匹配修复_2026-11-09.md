# 2026-11-09 混合读屏与门店匹配修复记录

## 背景

11.11 大促期间京东 App 页面持续动画，`uiautomator dump` 会等待界面空闲，超过内部上限后整次超时。桌面 dump 稳定 2.4 秒，京东页面 11.8 秒失败；回滚 11-08 基线仍复现，排除代码回归。

## 两条读屏通道的实测边界（同一台 HBN-AL00，1260×2844）

| 页面 | u2 即时快照 | uiautomator dump |
|---|---|---|
| 京东首页 | 可读，212KB / 59 个文本节点 | 11.8 秒超时 |
| 外卖频道与商家列表（原生 Activity） | 可读，275KB / 110 个文本，含门店名、起送价 | 未逐一验证 |
| 搜索结果页（AllChannelsListActivity） | 可读，288KB / 156 个文本，含门店全名、评分 | 未逐一验证 |
| 门店页（小程序 WebView） | 不可读，13KB / 0 个文本 | 可读，2.48–2.84 秒 / 87 个文本，含商品、购物车、去结算 |
| 商品详情页（弹窗） | 不可读（推断，同类 WebView） | 手动进入并静止后 2.4 秒可读，采集流程进入时曾持续超时 |

结论：u2 覆盖原生页面，dump 覆盖 WebView 页面，两者互斥（u2 占用无障碍时 dump 失败）。按页面切换是当前唯一能在大促期跑通的方式。

## 已提交的修复

1. **混合读屏**（`a99d372`）：`AndroidSession.setTreeMode('u2'|'dump')`；u2 模式读到 0 个文本节点时自动回落 dump。采集从首页/列表开始用 u2，进入门店前切 dump。
2. **预热接入 u2**（`8ccdbec`）：`live-single-pilot --from-home` 预热阶段先切 u2，首页 dump 不再阻塞启动。实测预热 2.5–3.8 秒通过。
3. **门店匹配改控件树直配**（`bdb7f72`）：搜索结果页是原生页，直接在 u2 树里按门店名匹配并点击，不再依赖模型定位（2–5 秒且易失败）；模型保留为兜底。
4. **零宽字符修复**（`bdb7f72`）：u2 读到的门店名带 `\u200b` 零宽空格，`\s` 无法剥离，导致文本匹配永远失败、回落到模型。`normalizeKey` 现在统一剥离零宽字符并把全角 `＆`、括号转半角。
5. **u2 启动重试**（本轮）：`startTimeoutMs` 10 秒改 15 秒；启动失败重试一次，仍失败时区分「进程活着但不可达」与「没起来」并抛出。

## 实测进展

- 混合读屏后单次采集读屏耗时从 100+ 秒降到 2.1–5.5 秒（7 次读取）。
- 链路目前稳定走到「搜索后门店匹配」并通过了读屏阶段，尚未跑通完整采集。
- 门店匹配的零宽字符修复与树匹配尚未真机验证（本轮 DSH Bash 执行器间歇故障，采集服务多次启动失败；且测试手机前台被其他应用占用）。

## 恢复验证步骤（手机空闲时）

1. 确认手机前台空闲、未锁屏。
2. `npm run acceptance -- --run`（或先单次 `live-single-pilot --from-home`）。
3. 若门店匹配通过，继续观察门店页 dump 与详情页读取。
4. 全部单次通过后再跑 20 次批次并冻结基线。

# 京东采集技术基线与竞对接入

2026-11-08。技术结构已实现；本轮连续真机结果在 19 号文档和对应批次报告中登记。本文件不提前宣布稳定性验收通过。

## 一页读懂

当前先把京东的一家门店、一款指定单品采稳，再接入美团和淘宝闪购。BD 保存清单后点击开始采集，后端独立核对店品、读取报价和费用、恢复购物车。模型负责读页面和辅助识别，程序决定哪些动作能执行、哪些金额能发布。

本版保留 Node.js、TypeScript、SQLite、Midscene Android、ADB 和可替换的视觉模型 API。不新增消息队列、图数据库或第二套手机执行器。页面本体用稳定编号连接业务含义、页面位置、校验规则和原始证据，不需要为了本体治理先上图数据库。

有效报价与完整流程分别判断：取得已核对金额才能算报价有效；本次加购自动恢复后才能算本轮完整结束。本机单店验收不能证明全部门店、全部机型、后台锁屏和多设备生产能力。

## 固定下来的模块边界

| 模块 | 负责什么 | 后续接竞对时怎样处理 |
|---|---|---|
| 清单与店品关系 | 稳定商品编号、清单版本、同店同规格关系 | 共用；每个平台分别确认店铺和商品，不能照抄京东编号 |
| API 与调度 | 请求幂等、立即返回任务编号、设备和账号互斥、有限重试 | 共用；各平台进入各自适配器 |
| 平台页面适配 | 搜品牌、认分店、找指定商品、打开规格、加购和恢复 | 各平台独立维护；京东已校准的控件不代表竞对也有效 |
| 页面本体与地图 | 对象、字段、页面状态、动作前后条件和版本快照 | 业务含义共用；页面状态、定位和证据分别验证 |
| 模型服务 | 真实 API、结构化读数、调用时间和用量 | 共用服务接口；提示、样本和每个平台的核验结果留版本 |
| 报价检查 | 金额转分、未知与零、模型和页面读数、费用口径 | 共用规则；不同平台显示标签分别绑定 |
| 证据与执行记录 | 脱敏截图、字段位置、节点状态、错误、耗时 | 共用；历史地图和失败结果不覆盖 |
| UE 页面与比较 | 选清单、开始采集、显示真实报价、费用、证据和失败 | 共用后端结果；未接入平台显示未取得，不补模拟价格 |

主要实现：`src/adapters/android-collector.ts` 为连续任务与动作检查；`jd-shelf-collector.ts` 保留历史扫描，同时承载现有京东导航。新任务不调用排名。`checkout-reading.ts` 读取结算明细；`domain/page-ontology.ts` 管理业务字段和地图版本；`application/competition.ts` 管理清单、任务及结果；`src/ue/collection.ts` 为实际入口。未来拆文件以维护需要为准，不为目录整齐改动已验证行为。

## 一次任务怎样完成

1. 冻结清单版本、目标规格、数量、账号、配送和优惠条件，取得手机使用权。
2. 确认当前页面。已有近期同店证据且当前身份一致时继续；首次、过期或身份不明时核对完整分店和地址。不能把首条搜索结果当作同店证据。
3. 打开指定单品，核对规格，保存现价证据。找不到或规格不明时停止，不换其他商品。
4. 记录加购意图，加一份并核对实际购物车。界面读取失败时先检查状态，不能盲目再点加购。
5. 读取结算与只读费用明细，保留每屏时间；应付变化时不把多屏拼成一笔报价。
6. 模型与独立页面读数逐字段核对。模型不执行自由下单流程；未知费用不填零，不用总额倒推费用。
7. 使用独立恢复时间，仅移除本次商品，核对空购物车并保存证据。无法确认时暂停该设备。
8. 发布报价和执行结果，分别展示取得报价时间、最终结束时间和恢复状态。所有失败计入测试报告。

商品模型读取与进入结算并行，结算模型读取与恢复购物车并行。每个节点单独计时，因此阶段时间不能简单相加。主耗时还需按本轮数据确认，不能仅用模型调用时间代表整轮速度。

## 接入美团、淘宝闪购时的最小检查表

| 检查 | 通过依据 |
|---|---|
| 具体入口 | 应用、版本、主应用频道或独立应用、账号与配送条件分别登记；来源使用条件如实记录 |
| 页面样本 | 门店、菜单、规格、购物车、结算、费用及恢复分别取得脱敏样本；未验证状态不能直接启用 |
| 同店 | 品牌、完整分店、城市和营业地址或已核实平台编号能核对；同品牌不同店测试会停止 |
| 同品 | 同名近似、容量不同、规格缺失、单品与套餐混淆会停止；相似品不进入同品价差 |
| 金额 | 原价与实收、起价、划线、免费、缺失、优惠已含在商品价中等样例可区分 |
| 动作 | 结算、领券结算、提交订单为不同动作；默认不得领券，测试特许单独记录，永不提交或支付 |
| 恢复 | 只移除本任务新增的一份；异常后已有商品不会被清空；恢复不明会暂停 |
| 连续运行 | 独立报告全部计划、有效报价、失败、未执行、恢复和分阶段耗时，不能用单次演示代替 |

跨平台比较仍要求同实体店、同规格和数量、已核实用户及配送条件，观察时差不超过五分钟。每个平台先完成自己的真实采集验收，再验证同品比较。平台之间不同会员或券资格必须展示，不能把“都是老客”视为全部条件相同。

下一阶段先校准美团页面并完成一品真实链路，再按同样方法接淘宝闪购。淘宝闪购现有来源条件尚未满足，不能通过复制京东本机试采登记来宣称可用；未满足时保留明确状态并先做离线样本适配。

## 基线保存

在连续测试结束后登记应用版本、代码文件摘要、页面规则版本、App 与模型版本、全部批次报告和脱敏证据位置。凭证、精确配送地址和用户原始页面不进入技术基线备份。更新平台适配或模型后使用同一套验收口径复测，不把旧结果继承为新版本通过。

## 一页读懂

本次研究面向平台补贴负责人，目标是判断现有方案是否值得立项，以及怎样降低错误采集和错误降补的概率。

**结论：方向可以继续，但“数据能稳定合法获得”和“价差能够证明超补”都没有得到项目证据支持。** 前者需要合同与实际样本，后者需要本平台实验。现有行业案例只能提供方法，不能替代这两项验证。

## 1. 审查方法与证据等级

先从“谁支付补贴、能改变什么、如何证明收益”推导数据需求，再用原方案查漏。研究中区分四种内容：

- **已核验的公开事实**：法规文本、官方接口页面、官方技术说明、论文中实际报告的内容。
- **来源方自述**：厂商 SLA、论文效果、企业内部实践。能证明对方这样描述，不能证明本项目可以复现。
- **本次设计判断**：范围、流程、预算假设、采样及验收建议。需要项目验证。
- **尚未核验**：实际授权、字段完整性、真实成本、市场覆盖率、用户愿意付费、收益提升。

检索优先采用平台官方文档、技术团队文章、监管机关和法院材料。对旧方案的市场份额、补贴总额、企业内部采集架构和宣传效果数字，没有逐一建立可追溯的一手证据；新版不依赖这些数字作决策。

“未检索到”不等于不存在；“页面可读”不等于合同允许；“论文有结果”不等于中文现制餐饮已验证。

## 2. 对原方案逐项挑战

| 问题与位置 | 反例或缺口 | 判定与修正 |
|---|---|---|
| README、01、03、Demo：以竞对价计算必要补贴与超补 | 用户可能为平台习惯、权益和履约付费；降补改变订单量 | 公式可作特定假设下的价格余量，不能直接命名为实际浪费或收益 |
| 03、04：补贴成本来自京东商家侧 | 商家账单未必包含平台全部资金项、订单级内部归集和长期激励 | 核对平台财务数据，不将商家结算等同平台成本 |
| Demo：补贴前价等于最终价加平台成本 | 平台成本不一定逐元等于消费者本次折扣；存在共同出资、返还、会员及履约成本 | 只在明确传导和口径假设下使用，生产字段必须分开 |
| 04：商家侧数据“偏差无” | 已成交订单是被选择的样本，未成交与不可见用户不在其中；退款与结算还有时滞 | 改为“对该字段可更接近事实，但有覆盖和时滞限制” |
| 03：本平台真实数据回校机器探针偏差 | 竞对券规则与样本机制不同，误差不一定可以迁移 | 不用本平台订单校正出竞对真实价 |
| 03：四类用户乘三时段即核心矩阵 | 新客与会员可重叠，各平台老客定义不同；每格少量观测不构成代表性 | 分轴记录；先回答具体场景，未覆盖格子留空 |
| 03：同一个用户跨平台不可控且无必要 | 自愿研究参与者可以本人查看三平台；同人配对可减少一些人群差异 | 同人配对与标准权益视角并存，但不假定三平台权益一致 |
| 03、05：同商圈同餐段作为比价控制 | 一栋楼与另一栋楼配送费不同；午餐期间也会变券或缺货 | 记录精确匹配的收货点代号和分钟级时间，无法匹配则降级 |
| 03：全套优惠栈固定顺序模拟 | 三平台、活动和版本的门槛、互斥及费用抵扣基础可能不同 | 报价观测优先，已知规则核对；不建无证据的最优券计算器 |
| 03：费用差异分解成责任方与动作 | 页面“平台券”不等于平台独资；金额项差异不等于用户行为原因 | 分开记金额解释、出资证据和因果假设 |
| 02、03：论文证明非标餐饮匹配可达约95% | DoorDash 是多品类目录链接；Q2K 是消费品商品名配对，有具体数据集限制 | 方法可迁移；不能把论文精度作为本项目验收结果 |
| 01、03、05：90% SKU 准确率可支撑运营 | 误配会产生错误资金建议；多个环节错误还会累积 | 试点关键映射全部人工确认，自动化采用高精度和拒绝判断 |
| 04：第三方打底占50%等配比 | 没有供应商样本、报价、来源和用途验收，百分比无事实基础 | 不保留比例；按可用来源和决策价值逐项接入 |
| 02、04：平台普遍使用若干境外风控产品 | 未取得三家外卖平台部署这些产品的一手证据 | 删除为事实的表述；只说明存在访问与自动化限制的可能 |
| 04、05：公开低频或采购后合规更稳 | 合同用途、技术措施、数据权益和客户交付限制可能仍不满足 | 不把采购、低频或匿名化当作安全港 |
| 01、06：法律禁止自动跟价/自动改价 | 规则重点是强制或变相强制及其他不合理限制 | 准确描述法律条件；第一版不自动执行是设计选择 |
| 05：3–5 家店、1–2 周判断降补不伤订单 | 样本量、分组、相关性及检验能力未给出 | 用实际统计条件确定实验，不能以“不显著”证明无损 |
| 05：识别10%预算超补作为指标 | 系统可能被激励去扩大“超补”认定 | 用净收益、误报、决策耗时和有效实验替代 |
| 06：专用时序分析库、复杂工作流、多角色 Agent | 少量门店没有已证实的规模或协作需求 | 单体应用起步；先证明数据、决策和付费 |

## 3. 对新版自身的反向审查

不能只指出旧方案的问题，却把新版的条件隐藏起来。

| 对新版的挑战 | 当前回答 | 怎样证伪或止损 |
|---|---|---|
| 平台已经有内部营销科学团队，为什么买 | 外部产品可能节约证据整理、异常复核和跨部门沟通时间；尚未证明有付费需求 | 与现有工具完成同一批任务，比较耗时、错误和采纳；没有改善就不继续扩功能 |
| 客户是否只愿意买竞对数据，不愿意买工作台 | 可能，这会改变核心商业模式 | 先核实购买意图；若只能靠高风险采集交付，停止该机会 |
| 低频样本会不会错过竞争活动 | 会，不能把它包装成实时监控 | 用于周级决策和特定实验；需要即时响应的客户另行核算合法来源与成本 |
| 真人面板是不是仍然有风险和偏差 | 是，主动提交与脱敏不能消除全部问题 | 来源与用途先审核；样本标签和缺失公开；不承诺总体代表性 |
| 无竞对数据也能优化补贴，为什么还要采 | 竞对变化可能帮助选择实验与解释异动，但其增量价值必须验证 | 比较“内部数据方案”和“增加竞对证据方案”，价值不够就缩减采样 |
| 小团队能否通过大平台采购与安全审查 | 未确认，企业接入可能成为主要固定成本 | 先以客户允许的隔离试点验证；把安全和接入成本单列，不用低价订阅覆盖无限定制 |
| 三大平台客户数量少，是否真是 SaaS | 有订阅复用潜力，但初期更像企业软件加服务 | 看第二客户能否复用大部分数据契约和流程；不把渠道变多等同客户数增长 |
| 不同客户是否产生竞争性信息交换 | 若共用未公开策略或数据，风险明显 | 按客户隔离，不默认建全行业补贴策略库 |
| AI 是否增加错误和维护成本 | 抽取、匹配辅助和说明可能有价值，但要计入人工返工 | 比较规则/人工基线与AI流程；无收益的模型步骤删除 |
| 降补省钱但伤长期用户价值怎么办 | 短期结果不足以回答长期问题 | 对拉新策略保留适当长期对照与复购窗口，未观察到的结果不写成确定收益 |

此外，代码选择京东第一条记录，并取全部竞对记录中的最低价。数据变成多时段、多用户后，这会跨场景取最低值；需要先形成合法、同口径的配对组，再计算比较。两类候选的优先级各自在列表中归一化，分值也不能解释成跨动作的同一收益尺度。

## 6. 本次复算的数量与预算

### 6.1 采样数量

每店2个商品组合 × 每周2次观察 × 4周：

- 10店：160个三平台任务，480条单平台报价。
- 50店：800个三平台任务，2,400条单平台报价。

这不是所有新老客、会员和餐段的全组合。若另加人群层、地址或入口，需增加任务量或减少其他覆盖。

若假设原计划报价中85%最终合格，以上分别是408条和2,040条；重复报价不是新的独立参与者。主方案预算下，每条有效报价的直接成本约6.25–10.98元与4.23–7.74元。85%同样是待验证假设，不是供应商实际成功率。

### 6.2 月直接成本

计算使用：三平台任务单价8–15元、10%额外重采、每任务复核3分钟、人工60元/小时。10店全部复核并计6小时例行支持，50店复核25%并计8小时支持；云与模型预算分别300–1,000元和500–1,500元。

- 10店下界：1,280 + 128 + 480 + 360 + 300 = **2,548元**。
- 10店上界：2,400 + 240 + 480 + 360 + 1,000 = **4,480元**。
- 50店下界：6,400 + 640 + 600 + 480 + 500 = **8,620元**。
- 50店上界：12,000 + 1,200 + 600 + 480 + 1,500 = **15,780元**。

不含开发、招募培训、法务、数据许可、企业接入、安全测评、接口费用、税费和获客，也不含平台实验补贴预算及客户侧额外人力。该成本表用于暴露规模和频率的影响，不是项目总报价。

### 6.3 实验数量级

采用双侧5%显著性、80%检验能力、两组等量、基线概率0.10、目标绝对差0.005的简化独立样本近似：

~~~text
n（每组）≈ 2 × (1.96 + 0.84)² × 0.10 × 0.90 / 0.005²
          = 56,448
~~~

正式设计应使用实际两组概率、统计方法、随机化单位、相关结构、非劣界限和指标方差。此处没有据该数字推定试点需要多少天，更没有把截图数当成实验样本数。

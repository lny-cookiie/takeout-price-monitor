# 三平台外卖采价：失败与修复知识库

用途：每次真机采集失败后，先把结构化事实自动记到 `.runtime/knowledge/attempts.jsonl`，再在这里整理成可复用的经验条目。下一次采集前先读对应平台的条目，避免重复踩同一个坑；修复过的经验尽量写成自动测试或真机复验记录，形成“越测越准”的闭环，而不是重复打补丁。

自进化流程（每次跑完必须执行）：

1. 失败/异常自动落记录（平台、错误码、清理状态、最近步骤）。
2. `npx tsx scripts/knowledge-report.ts` 查看汇总和“尚未整理”的错误码。
3. 把新错误整理成下方条目：现象、证据（运行编号/截图路径）、根因、修复方式、验证状态、适用范围（平台/版本/时段）。
4. 能写成代码判据或自动测试的就写进去；不能写的注明需要真机复验的步骤。
5. 开工前按平台检索本文件，先套用已有经验；条目验证状态从“已验证/待验证”如实标注，不把推测写成结论。

## F-01 淘宝：品牌搜索提交方式（2026-11-18 真机确认）

- 错误码：taobao_brand_search_failed
- 现象：输入品牌后点页面右上角橙色“搜索”按钮或按回车，只弹出搜索建议下拉，不进入门店结果页。
- 证据：运行 14ee4825、4b22dae1 等；截图显示“全部/麦当劳/搜索”建议列表。
- 根因：淘宝闪购换成了“建议优先”的搜索交互；真正的提交动作是**键盘右下角的搜索键**。
- 修复：输入后点击键盘搜索键（屏幕比例约 87.8% 宽、93.5% 高）；橙色按钮和回车作为兜底；提交后用截图差异与排序栏（综合/销量/速度）确认进入结果页。
- 验证：2026-11-18 多次单平台运行搜索步骤通过；淘宝完整成功记录 960fbe27。
- 备注：若键盘未弹出（yadb 直接注入文本），键盘坐标不可用，此时退回橙色按钮并核对页面跳转。

## F-02 淘宝：店内搜索是“边输入边出结果”（2026-11-18）

- 错误码：taobao_item_locate_failed
- 现象：输入单品名后继续点搜索键/橙色按钮，页面进入建议或空状态，商品行扫描找不到目标单品。
- 证据：运行 4442a70a；手动复现截图显示输入过程中商品列表已出现“板烧鸡腿堡 ¥26.5 +”。
- 根因：店内搜索实时刷新，不需要提交动作；多提交一次会打断列表。
- 修复：输入单品名后等待约 2.8 秒直接扫描商品行；扫描“橙色圆形加号→读该行文字→标题完全等于单品名才点”。
- 验证：960fbe27 完整成功。

## F-03 淘宝：门店名被 UI 截断成两行（2026-11-18）

- 错误码：taobao_store_unverified
- 现象：品牌页门店名显示为“麦当劳&麦咖啡(天津南开大学西…”+“堂食店>”，按单行匹配找不到完整门店名。

## F-04 淘宝：结算页整页读取偶尔只读到状态栏（2026-11-18）

- 错误码：taobao_payable_unverified
- 现象：结算页读取结果只有时间、网速、电量等状态栏文字，金额解析为空。
- 根因：本地小模型偶发把整页读成无效内容。
- 修复：判定“有效中文行少于 5 行”为无效读取，自动重拍重读最多两次；同时应付金额用底部金额栏二次读取做交叉校验。
- 验证：960fbe27 通过。

## F-05 淘宝：闪购标签点不动/已停在该频道（2026-11-18）

- 错误码：taobao_channel_entry_failed
- 现象：连续点“闪购”标签画面没变化（截图差异小于 1），被误判为失败。
- 根因：①冷启动后淘宝会记住上次标签，可能已经停在闪购频道；②页面被系统切到桌面时点击落空。
- 修复：先读顶部文字预检是否已经在闪购频道；已在该频道直接跳过点击。点击用屏幕比例（约 37% 宽、6.8% 高），用截图差异判断；连续失败时自动解锁并重新拉起淘宝再试。
- 验证：多次运行闪购入口 5-8 秒内完成。

## F-06 淘宝：模型定位长提示词会卡满 60 秒（2026-11-13 发现，2026-11-17 复核）

- 错误码：model_location_failed
- 现象：视觉定位反复超时 60 秒，整次采集被拖垮。
- 根因：本地 2B 模型对长提示词会一直生成，触发 Midscene 60 秒硬超时；短文字锚点约 2-4 秒返回。
- 修复：所有定位提示词改成短文字锚点；高频按钮用颜色/位置检测或标定比例替代模型定位。
- 验证：离线复现 + 真机多次通过。

## F-07 本地模型 JSON 输出被截断（2026-11-17）

- 错误码：model_invalid_output
- 现象：结构化 JSON 输出恰好 1800 token 被截断，解析失败。
- 根因：小模型在 JSON 约束下会一直生成到上限。
- 修复：新增纯文本读取通道（model.text）；JSON 解析加“提取最外层对象”容错；读图任务降低 max_tokens 并按行输出。
- 验证：淘宝/美团结算读文字改用文本通道后稳定。

## F-16 美团验证码/风控：识别、停止与降频（2026-11-18）

- 错误码：captcha_required / access_restricted / rate_limited
- 现象：短时间内多次完整采价后，美团跳出验证码/滑块；用户报告“频繁跳出验证码”。
- 证据/背景：2026-11-18 当天对美团反复跑了多次完整链路（搜索-进店-加购-结算-恢复），期间还有多次失败重试和冷启动强杀；这是典型的“高频重复同类行为”模式。
- 根因（推断）：平台风控按频率、行为模式和账号历史综合判定，不是某一次点击触发；我们测试账号在同一时段重复同类路径、频繁重启 App、失败后立刻重试，都会提高触发概率。
- 处理原则（合规）：**绝不自动点击验证码或尝试破解**。一旦出现，立即停止该平台、保存现场、暂停平台，等人工在手机上完成验证；冷却 45-60 分钟后再试，当天降低该平台次数。若验证码未处理继续跑，只会加重风控。
- 避免措施：
  1. 控制频率：美团单平台每小时不超过 4-6 次完整采价；组间隔至少 2 分钟；失败后冷却 60-90 秒再重试。
  2. 减少无效试验：先用离线截图/单步验证定位与解析逻辑，再跑完整真机链路；避免“改一点就跑一整轮”。
  3. 避免频繁强杀/冷启动：能用热启动就用热启动；不要连续强制停止应用。
  4. 不要连续反复“进店-返回-重试”；失败后先换平台，稍后再回来。
  5. 固定账号、设备、网络，避免异地/多设备切换触发风控。
- 已落地代码：`src/adapters/captcha.ts` 识别验证码字样；美团采集器在进店、加购、结算三个阶段先做验证码检查，命中即抛 captcha_required 且不做任何点击；调度器遇到 captcha_required/access_restricted/rate_limited 自动暂停平台；验收脚本遇到验证码/暂停立即停止批次，并在组之间默认冷却 120 秒。
- 真机证据（2026-11-18 21:44，运行 a8fb9c33）：美团搜索页读到提示文字“请输入图片中的内容”，确认那是图片验证码输入框而不是普通搜索框，当时工具把它当搜索框继续输入，最终报 meituan_search_failed。已扩展验证码识别词表并加入“搜索框提示语即验证码”的判断，命中直接抛 captcha_required；新增自动测试 tests/captcha.test.ts。
- 验证：识别逻辑与自动测试已通过；待下一次真机出现验证码时验证“自动停止+不误点”。

## F-17 京东：强杀后恢复到搜索页导致 page_not_ready（2026-11-18）

- 错误码：page_not_ready
- 现象：京东单平台偶发 33 秒左右失败，手机停在前台页面 com.jd.lib.omnichannelsearch.view.Activity.ChannelSearchActivity；重启应用仍然回到搜索页。
- 根因：京东会恢复上次停留的子页面，直接启动主 Activity 只是把旧任务带回前台，采集器把搜索页当成入口页，等待首页/结果超时。
- 修复：每次采集强制重启后检查前台 Activity，若处于搜索/详情/WebView 子页面，按返回键最多 3 次退回首页；并保留 openJdStore 内部的返回键兜底。
- 验证：连续两次京东单平台 partial 成功（¥33.23、¥32.73，quote_valid=true）。

## F-18 采集过程中手机被拔掉/断连（2026-11-19）

- 错误码：device_unavailable、app_version_changed（同一组内同时出现）
- 现象：三平台同组提交后 10 秒内全部结束，京东报 android_collection_failed，美团报 device_unavailable，淘宝报 app_version_changed。
- 根因：USB 连接被断开（用户取走手机），adb 设备列表为空；淘宝版本校验因此读不到版本，报成版本不一致。
- 处理：不需要清理购物车（三家 cleanup 都是 untouched），也不需要解除隔离（没有暂停记录）；等设备重新连接后正常重跑即可。恢复时先确认 adb devices 能看到设备，再确认三平台版本与登记一致。

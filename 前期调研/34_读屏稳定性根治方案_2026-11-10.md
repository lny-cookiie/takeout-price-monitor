# 读屏稳定性根治方案（2026-11-10）

## 问题定性
u2 读屏在这台设备上间歇失效：连续读取会从 251 节点退化为 63 节点（只剩状态栏），再读崩溃。这导致所有依赖 `read()` 的判断（isHome、页面断言、元素查找）全部误判，进而产生"点到会场"、"在全部商家里搜单品"等连锁错误。

**根因不是页面变化，是读屏通道本身不稳定。**

## 根治方案：读屏网关（Screen Gateway）

`src/adapters/screen-gateway.ts`

### 四级降级 + 有效性校验
```
L1 u2 直读（0.1-0.3s）→ 有效性校验
   有效 → 返回（正常路径零额外成本）
   无效 → L2
L2 重启 u2 再读（+2s，只在失效时付）
   有效 → 返回
   无效 → L3
L3 uiautomator dump（原生页可读，MRNX 页 0 字节）
   有效 → 返回
   无效 → L4
L4 视觉页面识别（只判页面类型，不找元素）
   有效 → 返回
   无效 → 抛 screen_unavailable（禁止静默返回空）
```

### 有效性判据（关键）
不能只看"节点数 > 0"——状态栏也有节点。必须检查**页面特征词**：
`外卖|团购|我的|搜索|评分|月售|起送|配送|门店|商家|购物车|去结算|加入购物车|商品|点菜|评价|附近|推荐|热门|历史`
一条都不命中 = 只有状态栏 = 无效读。

### 效率保证
- 正常路径：u2 一次读 + 纯文本匹配（微秒级），**零额外 adb 往返**
- 失效时：重启约 2s，一次性成本
- 全失败：显式抛错终止，不带着空数据往下跑

## 配套：页面断言层
`src/adapters/page-assert.ts`
- 8 个节点页面身份定义（home/takeout/search/results/store/inStoreItem/item/checkout）
- 偏离检测：会场/限时抢/立即抢购/团购券/直播 出现即判 unknown
- 断言失败自动 back 最多 4 次，仍失败抛 `page_assert_failed`
- 复用已读节点，零额外读屏

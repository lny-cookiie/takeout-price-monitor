这个演示用模拟数据展示四件事：

1. 三平台到手价怎么算。
2. 京东与最低竞对的价差怎么拆到菜单、活动、券、履约。
3. 京东的补贴有没有补多，必要补贴线怎么算。
4. 价差和超补怎么排成城市运营的两栏一页纸。

它不包含真实采集、POI 匹配、SKU 匹配和完整券规则。历史设计见 [03 方案](../03_第一性原理与方案设计.md) 和 [06 架构](../06_Agent技术架构.md)。Demo 仅用于查看早期输出形式。

## 计算口径

到手价：

```text
到手价 = 商品原价 + 打包费 + 配送费
         - 商家优惠 - 平台券 - 会员权益 - 支付优惠
```

价差：

```text
价差 = 京东到手价 - 最低竞对到手价
```

正数表示京东更贵，负数表示京东更便宜。价差分解把总价差逐项拆到七个业务杠杆，分解之和等于总价差。

超补：

```text
目标价 = 竞对到手价 - 目标优势
必要补贴 = max(0, 京东补贴前价格 - 目标价)
超补 = max(0, 实际补贴 - 必要补贴)
```

`京东补贴前价格 = 京东到手价 + 平台补贴成本`。这个算法假设商家折扣不变，只调平台补贴。超补金额按单次观测计算，乘订单量才能估算月度可节省金额。

优先级：

```text
优先级 = 价差或超补 × log(1 + 月 GMV)
```

价差和超补各自归一化到 0 到 100。它只用于排序，不代表真实收益。实际业务里还要加可修复性、战略匹配、补贴预算等约束。

## 输入格式

以下仅描述历史模拟输入。不能通过直接替换 `sample_data.json` 接入真实数据，当前 Demo 缺少必要的场景与空值校验。历史字段如下。

| 字段 | 说明 |
|---|---|
| `store_id` | 统一门店 ID |
| `sku_id` | 统一商品 ID |
| `platform` | 美团、淘宝闪购、京东外卖 |
| `list_price` | 商品原价 |
| `packaging_fee` | 打包费 |
| `delivery_fee` | 配送费 |
| `merchant_discount` | 商家满减或折扣 |
| `platform_discount` | 平台券、红包 |
| `member_discount` | 会员价、会员券 |
| `payment_discount` | 支付立减 |
| `final_price` | 结算页到手价 |
| `platform_subsidy_cost` | 平台为这一单实际掏的补贴，只有京东侧有值 |
| `captured_at` | 采集时间 |
| `probe_id` | 采集点编号 |
| `account_type` | 新客、老客、会员、非会员 |

真实数据必须遵循当前治理表。历史 Demo 未实现该契约，且会把缺失补贴成本当成零，因此不能用于生产。未知竞对补贴成本应保留未知，不能填成零。

## 已知限制

1. 数据是模拟的，价格和店名都是虚构的。
2. 只做单 SKU 比价，没有做标准篮。
3. 没有模拟券的门槛、互斥、上限，只做了金额相减。
4. 没有做 POI 和 SKU 匹配，输入假定已对齐。
5. 没有接实时采集和工单系统。
6. 目标优势固定为 1 元，真实场景要按品类、商圈、价格带用转化数据校准。

这六个限制对应下一步的工作包，按优先级排：先做真实截图解析和匹配，再做标准篮和券规则，然后接采集和工单，最后用增量实验校准目标优势。
